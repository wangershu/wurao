# 风险清单

## 已识别、尚未处理的（按影响排序）

1. **启动时规则恢复在主线程**（`restoreRules`）：现在 2.8 万条实测不卡，
   但它随规则数线性增长 —— 真到十万条量级（接 close.txt 那种表）很可能 ANR。
   修法：挪到后台线程 + 加载完刷新界面。
   **为什么现在没做**：眼下实测不触发（验证过 ANR 新增 0），改它要动界面状态刷新，
   风险比收益大；等规则数再上一个量级再动。

2. **每次 tick 仍要线性扫一遍全部规则**（`activeRules`）：过滤本身很便宜，
   但 2.8 万条时每次页面切换都要扫两遍。已经用 `RuleIndex` 挡掉了"每条规则各遍历整棵树"，
   剩下的这一层目前不是瓶颈。要彻底解决就按包名建索引（配置变更时建一次）。

3. **风险级四件套只在对美团的一次验证里看过**：摇一摇真实拦到过，
   组件/DNS/SDK 三项装配正常但没撞到触发场景。默认全关，真要长期开建议一次开一个、观察两天。

4. 订阅源可用性：大圣那份（dy_ys88）是旧格式且偏旧，已不做；AIsouler 那份写着"已停止维护"。
